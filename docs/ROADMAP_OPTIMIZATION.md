# 调研路线的第一轮落地

对应 [相似项目调研](../reports/related_projects_and_roadmap_2026-10-13.md) 的近期阶段。沿用现有 CaP、可信 Runtime、串口后端及 WebUI，本轮只更新电脑侧程序，ESP32 仍使用 v1.9 / PARAM2 / pwm-stream-v2。

## 统一动作可用性

模型反馈与 WebUI 使用 `robot/physical_status.py` 的同一张停稳预检表。传感器是否有效来自后端公开读取方法，其时效限制与模型实际读取一致：测距最多 400ms（含固件报告年龄），姿态最多 500ms（电脑收到数据后的年龄）。断开的设备不会返回缓存姿态。

| 动作 | 主机预检要求 |
| --- | --- |
| 闭环前进、定距后退、转弯 | 已连接、无会话故障、停稳 READY、有效姿态/航向；定距后退还要求 PARAM2 |
| approach 测距接近 | 上述条件及有效测距、PARAM2 |
| 持续手动 PWM | 健康停稳、支持直接 PWM 的 PARAM2；不依赖 BMI |
| 旧持续模式 | 前进依赖航向，其余方向不依赖航向 |
| 固定 0.8 秒手动后退 | 健康停稳，不依赖航向 |
| 停止 | 连接时始终可以请求，不受运动故障条件限制 |

该表用于停稳时的网页提示、方向按钮和模型判断。固件仍在收到动作时复查传感器和运动保护；主机表不会替代或解除固件保护。离线预览仍可生成计划。表也无法判断独立 5V 是否接入，或场地是否安全。

PARAM2 连接状态下，可信校验层根据当前传感器事实独立检查生成计划，包括策略库命中；WebUI 每段动作前再次检查。即使模型忽略“测距无效”，`approach` 也会被拦截，原始模型输出保留在错误详情。PARAM1 没有这里使用的姿态类型回传，继续由固件检查；离线生成不以缺少设备反馈为由拒绝预览。

故障提示区现在区分航向失效、速度保护、USB/串口失效和其他会话故障，显示相应恢复方法并保留原始故障。恢复需要显式操作，不自动重新执行运动。

## 策略复用的配置兼容性

保留现有“明确字面动作 + 已完成反馈 + 停稳”的复用规则，兼容合约升级到 `physical-explicit-literals-v2`。除了能力 API 和参数范围，还比较：

- 固件版本、固件报告的构建标识、前方保护配置和直接 PWM 支持情况。
- 电脑侧测距偏移值；DEMO 与实车仍分库。

开机 ID、位置、航向及暂时的传感器健康状态不进入配置指纹，避免每次开机都无意义地失配。每次复用仍重新校验代码并执行新动作，读取当前反馈。执行期间配置变化的记录不能成为已验证策略。预览到执行之间配置变化时，需要重新生成。

旧 v1 条目保留在文件中但不会命中 v2；下一次同配置成功执行后形成新记录。因此更新后第一次相同任务可能仍请求模型。这不是“语义相似就执行”的缓存，也不会复用失败动作或测距动态任务。

**边界：** 当前固件没有上报轮径、编码器校准版本及硬件唯一身份，记录中明确标为 `not_reported_by_firmware`，不能宣称已验证完整机械配置。修改轮子、编码器标定或更换设备后，应清空已验证策略库；后续可在固件上报这些标识后扩展兼容检查。

## 遥控计时

| 显示 | 测量方法 | 含义边界 |
| --- | --- | --- |
| 网页往返 | 浏览器同一 `performance.now()` 计时，发出控制消息到匹配序号应答 | 包含浏览器调度、传输和服务处理；不是车轮运动延迟 |
| 服务处理 | 服务端收到完整帧后到准备应答的 `perf_counter()` | 不含浏览器或串口固件确认时间 |
| 本次按住→固件确认 | 电脑同一单调时钟，从首次串口发送到同 session 的首次 TELEOP_ACK | 确认固件收到当前按住命令；不代表车轮开始转动 |
| 最近确认年龄 | 电脑当前时刻减去当前按住 session 的最近 TELEOP_ACK | 是回传新鲜度，不是每次心跳的往返耗时 |

不同机器/浏览器的时钟没有相减；不通过扩大 250ms 运动租约掩盖延迟。保持每次按住独立 session、停止优先、松开停止、心跳过期停止和不重试运动。DEMO 不伪造固件确认耗时。

模型请求、校验、动作前停稳、固件运行及动作停稳等原有计时继续保留。模型调用是否跳过仍在任务诊断中记录，便于比较真实复用收益。

## 验证和下一阶段

新增离线回归覆盖配置变化失配、跨配置记录不学习、过期预览不执行、按动作区分传感器依赖、故障时停止仍可用、断开后的缓存姿态不可读、只接受当前 session 的首次固件确认。实车不自动运行；模型调试仅生成并校验策略。

2026-10-13 完整离线回归通过 515 项（严格警告模式）。真实 DeepSeek 预览验证了后退+转弯和无测距的单独转弯；还观察到模型在无测距时仍输出 `approach`，据此补充可信预检及回归，而没有放宽执行条件。网页在独立 DEMO 服务中检查，没有运行实车。

下一阶段建议先收集上述分项计时与故障记录，再决定是否需要优化串口频率或模型工作记忆；完整开机会话日志继续保存。轮速上限标定、外部地面位置验证和无线链路验证需要实物数据，ROS、视觉/VLA 则属于后续扩展。
