# 小车硬件接口讲解：看懂每根线为什么这样接

更新：2026-10-12。适用对象：你的 ESP32-S3、TB6612 双路驱动板、两台 N20 霍尔编码电机、BMI323 和黑色 VL53L1X 模块。

本文解释接口和现有接线，不要求你上电或测试，也不改变程序。最新的分段 CaP 模式已完成软件测试，并于 2026-10-12 收到一次两段任务的实车完成记录。测距采集与前方停车保护目前仍关闭。

这里的 GPIO 编号已对照当前固件。线色按你之前拍摄的电机板丝印和线束对应关系记录，换电机或线束时必须重新核对。

## 1. 先认识小车上各个部件的分工

| 部件 | 在小车上负责什么 | 主要接收或提供什么 |
| --- | --- | --- |
| 电脑 | 理解你的任务、生成和校验 CaP 代码、接收执行反馈 | 通过 USB 串口发送指令、读取结果 |
| ESP32-S3 | 执行电机控制、读取传感器、处理停止和反馈 | 输出方向/PWM 信号，输入编码器脉冲，通过 I²C 读传感器 |
| TB6612 驱动板 | 根据控制信号，把电源中的能量送给两台电机 | 接收控制信号与电机电源，输出电机驱动电压 |
| N20 电机和减速箱 | 带动轮子旋转 | 从驱动板接收电能，产生机械转动 |
| 霍尔编码器 | 告诉 ESP32 电机转了多少、朝哪个方向转 | 输出两路脉冲 C1、C2 |
| BMI323 | 提供加速度和角速度数据，帮助估计车体转动 | 经 I²C 返回测量数据 |
| VL53L1X | 测量镜头前方目标的距离 | 经 I²C 返回距离；当前程序暂停采集 |
| 5V 适配器 | 给驱动板的电机供电部分提供能量 | 输出直流电源 |
| 面包板 | 把若干连接点接到一起，方便搭线 | 本身不会计算，也不会产生电源 |

“接口”既可以指塑料插头、排针这种**连接形式**，也可以指供电、PWM、I²C 这种**电气用途**。孔数相同的插头，电气用途和线序也可能不同。

## 2. 所有接口先分成三类

### 2.1 电源接口：让部件工作

| 常见名称 | 通常表示什么 | 本车的例子 |
| --- | --- | --- |
| `3V3`、`3.3V` | 3.3V 电源 | ESP32 开发板向公共 3.3V 轨供电 |
| `VCC` | 电路供电正端；名称本身不规定电压 | TB6612 的 VCC、编码器的 VCC 在本车接 3.3V |
| `VIN` | 模块电源输入；允许电压取决于具体模块 | 黑色 VL53L1X 的 VIN 在本车接 3.3V |
| `VM` | 电机驱动电源正端 | TB6612 的 VM 接外部 5V 适配器正端 |
| `GND`、`G` | 电路共同参考点及电流返回路径 | ESP32、驱动板、传感器和适配器负端共地 |

**不能看到 VCC 或 VIN，就一律当成 5V。** 你这辆车的电源正端分成 3.3V 和电机 5V 两组。

### 2.2 信号接口：传递控制命令或测量信息

例如 GPIO12 发出方向信号，GPIO14 发出 PWM，GPIO10 接收编码器脉冲。

这些线连接的是控制逻辑。电机需要的主要能量走 `VM → 驱动板 → 电机 → 驱动板地/电源负端`，不会通过 GPIO14 的 PWM 线供给。

### 2.3 电机输出接口：把功率送到电机

TB6612 的 `AO1/AO2` 和 `BO1/BO2` 属于这一类。它们是受控输出，可以改变两端的电压关系，让电机改变转向。

电机的 M1/M2 应接到这些输出；编码器的 C1/C2 才接 ESP32 的 GPIO。

## 3. ESP32-S3 开发板：电源、GPIO、USB 和按键

### 3.1 为什么有两个 3V3 和多个 GND？

开发板把同一电源网络引到多个位置，方便接线。它们不会因为数量更多而变成几组独立电源，也不会让可供电流翻倍。

| 开发板标记 | 用途 | 你现在的使用方式 |
| --- | --- | --- |
| `3V3` | USB 供电时可从板上取得 3.3V | 接到公共 3.3V 轨，分给传感器、编码器和 TB6612 VCC |
| `GND` / `G` | 公共地 | 接到公共 GND 轨，并与电机适配器负端连接 |
| `5V` | 板级 5V 电源连接点，具体输入/输出方式由板子设计决定 | 当前方案不用它连接外部电机适配器正端 |
| `GPIOxx` / `IOxx` / 单独数字 | 可由程序配置的信号脚 | 按后面的 GPIO 对照表连接 |

官方 DevKitC-1 的引脚表也列有重复的 3V3 和 GND。不同厂商的 ESP32-S3 开发板排针位置可能不同，因此你应按板上丝印找脚，不能只按“左上角第几根”数。参见 [Espressif 开发板说明](https://documentation.espressif.com/esp-dev-kits/en/latest/esp32s3/esp32-s3-devkitc-1/user_guide_v1.0.html)。

### 3.2 GPIO 是什么？

GPIO 是“通用输入输出脚”。同一个脚可以在程序中设置为输入、输出，或连接到芯片内部的通信/PWM 外设。

在你的程序中：

- GPIO12/13 是输出，发送右电机方向控制信号。
- GPIO14 是输出，发送右电机 PWM。
- GPIO10/11 是输入，接收右电机编码器的两路信号。
- GPIO8/9 被配置为 BMI323 的 I²C 数据和时钟线。

GPIO 编号是程序使用的编号，不是面包板上的孔号。GPIO8 也不是“从上往下数第八根针”。GPIO 信号按本车的 3.3V 逻辑使用，不把外部 5V 直接送进信号脚。

### 3.3 USB、UART、COM5 是什么关系？

USB 是电脑和开发板之间的连接。UART 是一种串行通信方式，信息依次通过发送和接收通道传输。

带 USB 转串口功能的开发板，会让电脑把这条连接显示成 COM 端口。你当前使用 `COM5`，程序通过它发送动作、接收日志；COM5 是电脑分配的名称，换 USB 口或设备后可能变化。

有些 ESP32-S3 开发板有两个 USB 插座：一个经 USB 转串口芯片连接 UART，另一个接 ESP32-S3 原生 USB。官方板上原生 USB 使用 GPIO19/20；两种路径有区别。你当前固件使用 UART0 控制台，保持使用之前已经验证的 USB 连接即可。参见 [Espressif USB 与排针说明](https://docs.espressif.com/projects/esp-idf/en/v5.1.3/esp32s3/hw-reference/esp32s3/user-guide-devkitc-1.html)。

### 3.4 BOOT 和 EN/RST 两个按钮有什么用？

| 按钮 | 硬件层面的作用 | 当前小车程序中的作用 |
| --- | --- | --- |
| `BOOT` | 连接启动配置脚 GPIO0，在复位时参与选择启动方式 | 正常运行时，程序还读取它，用来停止和中止运动 |
| `EN` / `RST` | 让芯片复位，重新启动固件 | 重新开始初始化和校准，串口控制会话需要重新建立 |

同一个 BOOT 按钮在“开机/烧录”和“程序已运行”时可能承担不同作用。当前 v1.8 控制不要求长按 BOOT 解锁。

### 3.5 其他常见标记怎样理解？

| 标记 | 表示什么 | 与本车的关系 |
| --- | --- | --- |
| `TX` / `TXD` | 串口发送信号，方向相对于标记所在设备 | 当前经板上的 USB 转串口路径通信，不需另接 TX 跳线 |
| `RX` / `RXD` | 串口接收信号，方向相对于标记所在设备 | 当前不需另接 RX 跳线 |
| `ADC` | 该信号脚可接入模数转换器，测量允许范围内的模拟电压 | 当前接线没有用它测电机供电或电流 |
| `SPI` / `MOSI` / `MISO` / `SCK` / `CS` | 另一种数字通信接口的信号名称 | 当前两块传感器使用 I²C，未使用这些 SPI 信号 |

一个 GPIO 可能支持多个功能。丝印列出“可用功能”，实际使用哪一种由程序配置；不是每一种标记都需要接一根线。板上各脚的复用功能见 [Espressif 排针功能表](https://docs.espressif.com/projects/esp-idf/en/v5.1.3/esp32s3/hw-reference/esp32s3/user-guide-devkitc-1.html)。

## 4. TB6612 驱动板：每个接口都负责什么

### 4.1 为什么 ESP32 和电机之间需要驱动板？

ESP32 负责输出控制信号。电机需要能提供较大电流、还能切换驱动方向的电路，TB6612 承担这一工作。

TB6612 有 A、B 两个电机通道，每个通道都包含方向输入、PWM 输入和两个电机输出；`STBY` 共同控制两个通道的待机状态。`VCC` 给控制逻辑供电，`VM` 给电机驱动部分供电。接口定义见 [Toshiba TB6612FNG 数据手册](https://toshiba.semicon-storage.com/info/TB6612FNG_datasheet_en_20141001.pdf?did=10660&prodName=TB6612FNG)。

### 4.2 全部排针的用途及本车接法

从车尾朝车头看：**A 通道是右轮，B 通道是左轮**。

| 驱动板接口 | 用途 | 本车接到哪里 |
| --- | --- | --- |
| `VCC` | 驱动芯片控制逻辑电源 | 公共 3.3V 轨 |
| `VM` | 电机驱动电源 | 外部 5V 适配器正端 |
| 各个 `GND` | 地连接点 | 公共 GND，与适配器负端共地 |
| `STBY` | 两路驱动共同的待机/使能控制 | ESP32 GPIO15 |
| `AIN1` | A 通道方向输入 1 | ESP32 GPIO12 |
| `AIN2` | A 通道方向输入 2 | ESP32 GPIO13 |
| `PWMA` | A 通道 PWM 输入 | ESP32 GPIO14 |
| `AO1` | A 通道电机输出 1 | 右电机白线 M1 |
| `AO2` | A 通道电机输出 2 | 右电机红线 M2 |
| `BIN1` | B 通道方向输入 1 | ESP32 GPIO16 |
| `BIN2` | B 通道方向输入 2 | ESP32 GPIO17 |
| `PWMB` | B 通道 PWM 输入 | ESP32 GPIO18 |
| `BO1` | B 通道电机输出 1 | 左电机白线 M1 |
| `BO2` | B 通道电机输出 2 | 左电机红线 M2 |

早期只有一个电机时，B 通道控制脚曾接地。现在两个电机都已接入，BIN1/BIN2/PWMB 使用表中的 GPIO。

### 4.3 AIN1、AIN2 为什么要两根？

两根线的高低组合选择电机输出状态。以下只看 A 通道，B 通道同理：

| STBY | AIN1 | AIN2 | PWMA | 作用 |
| --- | --- | --- | --- | --- |
| 低 | 任意 | 任意 | 任意 | 待机，输出为高阻态 |
| 高 | 高 | 低 | 高 | 一个电气转向 |
| 高 | 低 | 高 | 高 | 相反的电气转向 |
| 高 | 高 | 高 | 高或低 | 短路制动 |
| 高 | 低 | 低 | 高 | 输出为高阻态，停止驱动 |

“高”在本车控制侧接近 3.3V，“低”接近 0V。方向组合与“车前进”的对应关系，还取决于电机两线连接和左右安装方式，固件已经使用你之前实测的方向配置。

该表来自驱动芯片的控制定义，PWM 为低时的制动行为还受输入组合影响；不能把所有“低电平”都理解为同一种停车方式。参见 [Toshiba 控制状态表](https://toshiba.semicon-storage.com/info/TB6612FNG_datasheet_en_20141001.pdf?did=10660&prodName=TB6612FNG)。

### 4.4 PWM 怎样影响电机？

PWM 会重复输出高、低电平。“占空比”表示一个周期中高电平所占的时间比例。方向一定、其他条件相同时，提高占空比通常能让驱动对电机施加更强的作用。

当前固件使用 20kHz PWM，也就是每秒约两万个周期。GPIO14/18 上传的是这种控制信号，TB6612 据此切换电机输出。

例如 50% 占空比，不意味着轮子一定以最大转速的一半旋转。实际转速还受负载、摩擦、供电、电机差异影响，所以程序要结合编码器反馈调节。

### 4.5 STBY 拉低和“轮子已经停下”一样吗？

不一样。当前 `motor_stop()` 先拉低 STBY，再清零 PWM 和方向脚。这会关闭主动驱动，轮子仍可能因惯性继续转一小段。

因此日志中既有“关闭驱动时的测量”，也有“关闭后的测量”和后续停稳 READY。这能解释为什么目标 100mm 时，关闭驱动后编码器估计最终可能超过 100mm。

### 4.6 驱动板应该亮灯吗？

电源灯是模块设计者可以添加的元件，不是 TB6612 工作所必需的功能。你照片中的板子没有明确可辨认的电源指示灯，黄色长方形元件不能当成亮灯依据。判断连接和工作状态应看供电、控制信号和反馈，不能只看是否亮灯。

## 5. N20 电机的六根线：两根驱动，四根编码器

### 5.1 你的线束对应关系

你拍摄的电机小板标有 `M1、GND、C1、C2、VCC、M2`。按当时照片，线色对应如下：

| 电机板标记 | 你的线色 | 用途 | 右电机 A 接到 | 左电机 B 接到 |
| --- | --- | --- | --- | --- |
| `M1` | 白 | 电机驱动端 1 | TB6612 AO1 | TB6612 BO1 |
| `M2` | 红 | 电机驱动端 2 | TB6612 AO2 | TB6612 BO2 |
| `VCC` | 黑 | 霍尔编码器电源 | 公共 3.3V 轨 | 公共 3.3V 轨 |
| `GND` | 蓝 | 霍尔编码器地 | 公共 GND 轨 | 公共 GND 轨 |
| `C1` | 绿 | 编码器第一路输出 | GPIO10 | GPIO4 |
| `C2` | 黄 | 编码器第二路输出 | GPIO11 | GPIO5 |

**你的这套电机线束，黑线是编码器 VCC，蓝线才是 GND。** 适配器的黑线又是负端。这是不同线束采用了不同配色，判断依据必须是各自标记和已经核对的线序。

### 5.2 霍尔编码器为什么需要单独供电？

M1/M2 接的是电机绕组。编码器是电机尾部的电子电路，需要自己的 VCC/GND 才能正常输出信号。

所以，电机能转不代表编码器一定有信号；编码器有供电，也不表示 M1/M2 已获得驱动。

### 5.3 C1、C2 怎样告诉程序方向？

转子转动时，编码器输出两路相互错开的高低变化。程序观察两路变化的先后关系，判断方向；统计变化次数，估计转动量。

一个理想化的两路状态序列如下：

```text
一个方向：00 → 01 → 11 → 10 → 00 → ……
相反方向：00 → 10 → 11 → 01 → 00 → ……
```

这里的 00/01 等表示 C1/C2 的两位状态。具体哪种顺序记为正数，由接线和计数配置决定。

你车的实测配置是：车向前时，右轮 A 的原始计数为负方向，左轮 B 为正方向。程序已做方向转换，不能因为一边计数是负数就直接认为接错。

编码器反映的是转动。程序结合轮径和标定，将转动计数换算成估计距离。轮子打滑、线材拖拽等情况，会使编码器估计和实际地面行程存在差异。

### 5.4 白色六孔插头为什么插不进杜邦线？

六孔只是触点数量。小插头和杜邦排针还可能有不同的触点间距、金属端子尺寸、外壳定位结构。

杜邦线常用 2.54mm 间距，而你这套小插座的具体系列和间距，不能仅凭照片确认。它应使用匹配的插座或转接线；不能因为都是六孔就直接互插，也不能只按外壳方向猜线序。

线束转换只改变连接形式，每一根线的 M1/M2/VCC/GND/C1/C2 身份仍须保持对应。

## 6. BMI323：供电、I²C 和中断脚

### 6.1 它提供什么数据？

BMI323 内含三轴加速度计和三轴陀螺仪。加速度计提供各方向的加速度测量，陀螺仪提供各方向的角速度测量；它们经数字通信接口交给主控。芯片还提供可配置的中断输出。参见 [Bosch BMI323 产品说明](https://www.bosch-sensortec.com/en/products/motion-sensors/imus/bmi323) 与 [数据手册](https://www.bosch-sensortec.com/media/boschsensortec/downloads/datasheets/bst-bmi323-ds000.pdf)。

本车程序利用这些数据进行静止校准、重力方向处理和相对转角估计。转弯结果表示“相对开始时转了多少度”，不会直接给出房间里的绝对坐标，也不能提供指南针式的绝对朝向。

### 6.2 你的六个排针

| BMI323 模块接口 | 用途 | 本车接法 |
| --- | --- | --- |
| `3V3` | 模块电源输入 | 公共 3.3V 轨 |
| `GND` | 地 | 公共 GND 轨 |
| `SDA` | I²C 数据线 | ESP32 GPIO8 |
| `SCL` | I²C 时钟线 | ESP32 GPIO9 |
| `INT1` | 可配置的事件/数据中断通知输出 | 当前不外接 |
| `INT2` | 另一路中断通知输出 | 当前不外接 |

INT1/INT2 可以通知主控“有新数据或某个事件发生”。当前固件通过 I²C 读取数据和状态，所以这两根中断线不是现阶段必须连接的线。中断通知的用途见 [Bosch 中断映射说明](https://www.bosch-sensortec.com/media/boschsensortec/downloads/datasheets/bst-bmi323-ds000.pdf)。

### 6.3 白色插座和排针是什么关系？

白色插座是一种连接器，排针是另一种连接器。白色插座的具体线序和它与排针之间的连接关系，需要该模块的说明或电路图确认，不能仅凭插座外观推断。

你现在使用的是已焊接的排针，按表连接 3V3、GND、SDA、SCL 即可。排针的短端用于穿过板孔焊接，长端留作外部连接；焊点负责可靠电气连接，单纯把针插进板孔不等于已连接可靠。

### 6.4 为什么放在左后方也能测转弯？

传感器牢固固定后，会随车体一起转动。它在左后方也能为当前程序提供角速度数据；安装方向和小幅倾斜需要通过校准及坐标处理考虑。

偏离车体中心会影响转动时的加速度测量，所以不能把模块读到的所有加速度直接当作车体中心的运动。你目前主要用它辅助方向保持和相对转角估计。

## 7. VL53L1X：测距模块上的六个接口

### 7.1 它测的是什么？

VL53L1X 使用光的飞行时间进行距离测量。它提供镜头视场内目标的测距结果，不直接给出二维地图或小车的位置。参见 [ST VL53L1X 产品说明](https://www.st.com/en/imaging-and-photonics-solutions/vl53l1x.html)。

你使用的是之前商品图中的黑色模块，下面按它的板上标记解释；商品图里的红色模块不能作为黑色模块的供电或排针顺序依据。

### 7.2 各脚用途

| 黑色模块接口 | 用途 | 本车接法/使用状态 |
| --- | --- | --- |
| `VIN` | 模块电源输入 | 沿用已验证的公共 3.3V 供电 |
| `GND` | 地 | 公共 GND 轨 |
| `SDA` | I²C 数据线 | GPIO6 |
| `SCL` | I²C 时钟线 | GPIO7 |
| `GPIO1` | 模块的中断通知输出 | 当前不外接 |
| `XSHUT` | 硬件关断控制输入，低电平有效 | 当前不由 ESP32 单独控制；正常工作需要模块使其保持有效高电平 |

GPIO1 的用途是告诉主控有测量事件，不是“测距数值从这里逐位输出”。XSHUT 可以关断芯片并使其退出 I²C 通信；使用多个同类测距器时，程序也可配合该脚逐个初始化并配置地址。GPIO1、XSHUT 和 I²C 的芯片定义见 [ST 数据手册](https://www.st.com/resource/en/datasheet/vl53l1x.pdf)。

**VL53L1X 模块上的 GPIO1，不等于 ESP32 的 GPIO1。** 两者只是各自器件的命名。

VIN 是模块输入，模块上可能还包含稳压、上拉或电平转换电路。裸芯片的引脚电压要求和模块 VIN 允许范围不能混为一谈。这里沿用本车已经使用的 3.3V 接法，不据其他商品图改接 5V。XSHUT 不应悬空失去有效电平；是否由板上上拉维持，要以该模块的电路设计为准。

### 7.3 接好了，为什么当前没有测距数据？

物理接线与软件启用是两件事。按你此前的要求，当前固件暂停测距采集，前方停车保护为 `front_guard=OFF`。

以后把镜头固定朝车头，再恢复采集和保护，测距结果才能参与控制。仅仅插好 SDA/SCL，并不会自动打开避障。

## 8. I²C、PWM、编码器、串口怎样区别？

| 接口/信号 | 信息主要朝哪里传 | 通过什么传递信息 | 本车用途 |
| --- | --- | --- | --- |
| I²C：SDA + SCL | 主控和传感器之间 | 带时钟和设备地址的数字通信 | 读 BMI323；预留 VL53L1X |
| PWM | ESP32 → 驱动板 | 高低电平的持续时间比例 | 调节电机驱动强度 |
| 方向输入 IN1/IN2 | ESP32 → 驱动板 | 两根线的高低组合 | 选择电机转向/输出状态 |
| 编码器 C1/C2 | 编码器 → ESP32 | 两路错相脉冲的顺序和数量 | 反馈旋转方向、转速和转动量 |
| INT / GPIO1 中断 | 传感器 → 主控 | 电平变化通知事件 | 本车暂未接入这些通知脚 |
| USB 串口 / UART | 电脑 ↔ ESP32 | 字节组成命令和反馈 | CaP 下发动作，ESP32 返回结果 |

### 8.1 SDA 和 SCL 是怎样配合的？

SDA 承载通信数据；SCL 提供通信时钟。ESP32 在这辆车上负责发起通信，传感器根据设备地址响应。

I²C 通常需要上拉使线路在无人拉低时保持高电平，上拉电源应与双方的逻辑电平要求匹配。模块可能已带上拉，当前接线沿用已经验证的配置。

设备地址可理解为“这条通信线路上要找谁”：你的 BMI323 之前响应 0x69，VL53L1X 通常使用 7 位地址 0x29。地址不是 GPIO 编号，也不是电压。

当前程序用了两组线路：BMI323 是 SDA8/SCL9，VL53L1X 是 SDA6/SCL7。即使 I²C 可以让兼容设备共用一组线路，也不能只把线合并而不修改程序配置。

### 8.2 为什么不能把 SDA 和 PWM 当作同一种信号线？

它们都可能由 GPIO 输出电平，但接收方对电平变化的解释不同：传感器在 SDA/SCL 上读通信协议，驱动板在 PWM 上读驱动控制。

同样的杜邦线可以用来连接这些接口，不代表两种接口能随意互换。

## 9. 电源适配器、公共轨和面包板

### 9.1 5V、3A 分别是什么意思？

你的适配器标注输出 5V、3A：5V 是额定输出电压，3A 是其标称供电能力，不是强行向所有连接的元件灌入 3A。实际电流由负载及电路状态决定。

这也不代表连接线、杜邦接点和面包板接点都能持续承受 3A。电机供电回路和低电流信号线承担的任务不同，接点松动、接触电阻会带来压降和发热。

适配器插头转换件上的红/黑端子用于引出直流正负端。本车沿用已核对的接法：适配器红线接 VM，黑线接公共 GND。线色须结合转换件标记确认。

### 9.2 为什么正端分开，负端却要共地？

ESP32 输出的高低电平，是相对于自己的 GND 而言；驱动板也相对于自己的 GND 解释这些电平。两者共地，才能有一致的电压参考。

目前连接可以按下面两条电源路径理解：

```text
电脑 USB → ESP32 开发板 → 3.3V 公共轨
                            ├─ TB6612 VCC
                            ├─ 两个编码器 VCC（本线束黑线）
                            ├─ BMI323 3V3
                            └─ VL53L1X VIN

外部 5V 适配器正端 ──────────── TB6612 VM
外部 5V 适配器负端 ─┐
ESP32 GND ──────────┼─ 公共 GND ─ 驱动板、编码器、传感器 GND
                   └─ 所有控制信号使用共同的参考地
```

公共 3.3V 轨是把同一个 3.3V 电源分给多个负载。**电机 5V 正端保持单独接 VM，不与 3.3V 公共轨接在一起。**

电流返回路径也要考虑接触质量。电机的大电流经过有接触电阻的公共连接段时，会影响其他电路看到的地电位；共地并不意味着接点压降可以忽略。

### 9.3 面包板哪些孔内部相通？

常见面包板中间区域，每个编号对应两组五孔：

```text
同一编号：a—b—c—d—e    中间沟槽    f—g—h—i—j
          这五孔相通              这五孔相通
          两组之间不相通；不同编号通常不相通
```

侧边红/蓝长线表示供电轨位置，但颜色不会决定电压。你把红轨接 3.3V，它才是 3.3V；把蓝轨接 GND，它才是 GND。一些板子的长电源轨在中间分段，左右两侧通常也不自动相通。

因此“看起来在同一条红线旁边”不一定意味着电气连接。需要确认具体面包板的内部连接；若用万用表通断档确认，应在断电状态下进行。

### 9.4 一个孔已经插满，怎样理解“分线”？

分线是利用内部相通的空孔，或用合适的分配连接件，把同一个电气节点引到多个地方。不是把两个金属针硬塞进同一个孔。

例如，3.3V 电源轨只需有一根线与 ESP32 3V3 连接，其余相通孔即可分别连接各个低电流负载。信号脚分线也必须考虑接收方是否允许共用信号，不能把不同 GPIO 输出直接并在一起。

## 11. 从一句 CaP 指令，看到这些接口怎样合作

以 `robot.move(0.10)` 为例：

1. 电脑端校验调用后，通过 COM5 发送前进 100mm 的串口指令。
2. ESP32 根据固件检查状态，设置左右电机方向、STBY 和 PWM。
3. TB6612 从 VM 电源取得电能，通过 AO1/AO2、BO1/BO2 驱动两台电机。
4. 两个编码器经 C1/C2 输出脉冲；ESP32 计算转速和累计转动量。
5. ESP32 同时通过 SDA8/SCL9 读取 BMI323，用于当前方向保持与角度反馈。
6. 达到目标或出现停止条件时，固件关闭驱动，并返回测量及后续停稳确认。
7. 电脑端核对这些反馈，记录完成状态和耗时。

当前 VL53L1X 没有参与这一流程。新分段 CaP 模式会在一段动作完成并停稳后，把实际反馈交给模型判断是否继续原计划，但仍通过同一套硬件接口执行。

“底层接口正常”“代码已执行完成”“小车实际到了想要的位置”是三个需要分别判断的结果：串口反馈证明程序与接口流程，编码器/陀螺仪提供运动估计，实际地面位置还需要独立观察或测量。
