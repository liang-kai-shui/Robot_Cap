# v1.9 小车控制台：低延迟遥控、上下文和传感器动作

本轮先将已有 WebUI、Three.js 姿态、测距采样和手动后退整理上传为 `c4abcdd`，再进行本文件描述的优化。新增实车能力需要 **ESP32 v1.9 / PARAM2**；旧 v1.8 可以使用原有前进、转弯和短时后退，不能发送新指令。界面不在连接时自动运动。

## 使用入口

双击仓库根目录 `Start_Robot_UI.vbs`，打开本机控制台，选择 COM5 连接。模型与设置中填写 DeepSeek Key，只存在服务进程内存。更新后刷新页面；旧进程需要结束后重新双击启动。

- 默认勾选“持续按住模式”：按住 W/S/A/D 或方向按钮，持续前进/后退/左转/右转；松开停车，T 或 Esc 中止。浏览器失去焦点、进入后台、断线或停止接收确认也释放控制。最长一次按住30秒，需要松开再按。
- 取消“持续按住模式”恢复原先步进按钮，前进步长5–30cm，左右角度15–90度；旧手动后退保留0.8秒。
- 自然语言默认先生成预览，再点击执行。**主动勾选**“计划校验通过后自动执行”后，本次提交才会生成、校验、直接执行；没有连接健康停稳设备时拒绝自动执行。
- 历史每页6张卡片，支持搜索/状态筛选；动作以方向和距离标签显示，可展开模型生成代码及环节耗时。预览明确标记未执行。
- 独立诊断区显示模型调用错误、代码/API校验错误、执行错误及原始模型输出。未注册API、超界参数、循环和未停止策略会在运动前被拒绝。错误也进入本次开机历史，失败任务不会当作已经完成。

## 哪些地方提速

原实现：完整计划生成 → 每段新Worker → STOP/READY → 执行动作 → STOP/READY → 再请求模型审核 → 下一段再STOP/READY。实际动作已经规划完整，段间模型请求仍增加网络和推理等待。

当前默认完整计划仍一次生成、全量校验；每段仍由隔离Worker和原Registry/Runtime执行。段间只做**本地确定性检查**：全部调用成功、结果有效、设备无故障、收到停稳READY、任务未取消且未超时。通过后执行原计划下一段，不能追加/修复/重试动作。设置中仍可选择“每段请求模型审核”，恢复原审核路径。取消重复的动作前STOP；明确的最终STOP仍发送并等待确认。

固件保留300ms滑行测量，将驱动停止后的最短冷却由1000ms改为350ms，轮子无边沿确认由500ms改为150ms。READY仍同时要求电机输出全低、无待处理结果、无新边沿、无待解析帧。已经停稳的T仍确认和清空输入，但不重复冷却。

模型默认 `reasoning_effort=none`，可改低/高思考。将稳定的系统提示和注册API放在消息前缀，把变化的传感器和任务放后面，便于服务端前缀缓存。没有复用旧任务代码，也不在模型输出完毕前执行半个计划。缓存命中和实际模型延迟由服务决定，不能保证固定倍数提速。

遥控使用同源WebSocket持续连接，TCP_NODELAY，65ms浏览器心跳；不经过模型、Worker或完整动作等待。每次只允许一个未确认心跳，不积压动作，发送缓冲过大就断开。服务端每次确认签发200ms有效的挑战值，顺序号必须连续；过期/重放帧不能启动或续控，release始终优先允许。服务端200ms失联请求T，ESP32独立250ms租约过期切断STBY；旧租约编号不能重启运动。低延迟链路不是物理急停设备。

界面显示的是**浏览器↔本地服务往返时间**，不是电机响应总延迟。固件ACK、实际车轮速度另由串口回传。日志改为增量追加，避免每100ms重建350行DOM。遥测约250ms采样，SSE约100ms推送，不能把动画平滑度当作测量频率。

## 已开放的 CaP 接口

| 调用 | 单位/边界 | 实际含义 |
|---|---|---|
| `robot.move(0.10)` | 米，0.05–0.30，1mm步进 | 前进编码器闭环，BMI保持相对航向 |
| `robot.reverse(0.10)` | 米，同上，只接受正距离 | 后退编码器闭环，后方没有测距 |
| `robot.turn(-30)` | 度，绝对值15–90，0.1度步进 | 正数左转，负数右转，BMI相对角度 |
| `robot.approach(0.30)` | 前方净距米，0.10–1.00，1mm步进 | 持续前进直到传感器前方约30cm；不是前进30cm |
| `robot.get_distance()` | 返回米/毫米、原始毫米、有效性、时间 | 当前测距回传，无效/过期抛错 |
| `robot.get_attitude()` | 传感器轴roll/pitch、相对yaw，度 | 无效/过期抛错，不是绝对方向或地面位姿 |
| `robot.get_state()` | 会话状态字典 | 连接、停稳、固件、故障等 |
| `robot.stop()` | 无参数 | T确认加停稳READY |

模型仍只能生成逐行字面量调用并以stop结束，最多9次运动，有界只读观测；不开放连续遥控、Shell、任意循环或不存在的定位接口。Registry决定API是否真的存在；v1.8不发布v1.9动作。

示例：“后退10厘米，左转30度，停止” → reverse(.10)/turn(30)/stop。“走到距离前面30厘米的地方” → approach(.30)/stop。生成时把当前有效测距、姿态、会话状态传给模型；执行approach时重新读取并让固件持续检测，不能仅用生成时的读数换算一个固定前进距离。

approach只能向前：当前已达到目标或过近则拒绝，不自动倒退。驱动前再次确认测距；执行期间光学状态错误、总线错误或样本超200ms就切断驱动。最高行程1.5m、最长15s；接近目标时降速，并在目标前约12mm断驱动以留滑行量。完成后再次报告测距，接受目标-50mm到目标+25mm范围，超出则任务失败并停止剩余动作。该容差未经这台车新一轮实测标定，不能保证精确30cm；线材拖拽、镜头位置和目标反射会影响结果。普通move和手动遥控的前方保护仍为OFF。

## 开机上下文

ESP32 READY含随机 `boot_id`。同一服务、同一开机ID下断开再连接保留任务历史；收到重启标志或新boot_id清空模型上下文。停止本地服务后不会从日志恢复上一会话。旧固件没有boot_id，无法证明同次开机，重连时保守清空。

本次开机的完整任务保存在本地journal，包含预览、拒绝、失败、已完成动作。模型收到最近4条详细摘要和更早所有任务的紧凑摘要，明确标注执行状态；不只记最近4条。不把密钥、原始串口日志或任意历史代码注入提示。“转回去”仍仅逆序反向执行最近完整任务的转弯，不承诺返回地面位置。手动持续控制会使旧转回参考失效。日志下载可查看完整原始记录，模型摘要有长度边界；超长会话仍受模型上下文容量限制。

## 测距偏移标定

VL53L1X数据手册规定保证最小测距4cm；手几乎贴住镜头却显示3cm属于近场，不能据此整体减去3cm。以**镜头平面**量距离，摆一个平整、稳定的目标，建议140mm。填已知毫米值，点击“标定偏移”，采集20个不同时间的有效样本；波动范围超过20mm或样本不足则不应用。偏移=已知距离-样本中位数，限制±100mm。

WebUI同时显示原始值和校正值；偏移用于get_distance与approach的目标换算，不覆盖原始日志。偏移保存在本地 `runs/webui/range-calibration.json`，不上传GitHub、也不保存Key。此功能是**主机侧显示/动作偏移补偿**，没有运行ST的片内offset/crosstalk工厂校准，不解决所有距离下的非线性误差或覆盖玻璃串扰。

## 一手参考与取舍

- [本项目交互优化报告](../reports/interactive_optimization_2026-10-05.md)：模型负责子目标，确定执行与观测检查在可信侧；没有照搬虚拟地图真值。
- [ROS diff_drive_controller](https://control.ros.org/jazzy/doc/ros2_controllers/diff_drive_controller/doc/userdoc.html)：输入命令过期后停车，借鉴本地租约而不引入ROS。
- [ROS teleop_twist_keyboard](https://index.ros.org/r/teleop_twist_keyboard/)：持续重发需配合按键超时。本项目按真实keydown/up与指针捕获，不依赖操作系统重复按键延迟。
- [MDN WebSocket](https://developer.mozilla.org/en-US/docs/Web/API/WebSocket)：双向持续通道，没有内置背压；显式检查bufferedAmount和单个待确认心跳。
- [DeepSeek Chat API](https://api-docs.deepseek.com/api/create-chat-completion/) 与[前缀缓存](https://api-docs.deepseek.com/guides/kv_cache/)：关闭思考、稳定前缀；不承诺缓存一定命中。
- [ST VL53L1X数据手册](https://www.st.com/resource/en/datasheet/vl53l1x.pdf) 与[ULD标定手册](https://www.st.com/resource/en/user_manual/um2510-a-guide-to-using-the-vl53l1x-ultra-lite-driver-stmicroelectronics.pdf)：近场边界与已知目标偏移标定。主机补偿和厂商片内校准明确区分。

## 验证范围

Python回归覆盖旧协议兼容、PARAM2后退完整反馈、approach有效/无效/过期/过近/超差、偏移共享、模型校验失败不运动、自动执行模式、同开机重连/重启清空、完整历史、WebSocket掩码/长度/顺序/挑战超时/连接断开停车。C检查覆盖碎片化新指令、T优先、租约过期不能续期、旧session不能重启、禁止运动中换向和30秒上限。ESP-IDF5.1.2实编译通过。浏览器在明确离线DEMO上验证预览、代码卡片和新控件。

本轮最终本机回归 **444项通过（20.11秒）**，固件参数/租约C检查通过；完整ESP-IDF产物0x4aa60字节，1MB应用分区剩余71%。新版浏览器DEMO确认按住W后释放停车、后退代码预览、自动执行、测距接近预览与390px卡片布局。浏览器本机服务往返显示约0–2ms，只代表本机网页链路，不能当作真实电机响应时间。

离线测试和编译不能替代本车地面运动验证；v1.9本轮尚未烧录，等待拔下电机5V后更新。网页“模型与设置”已加入编译并烧录入口。新固件烧录后第一次接电应先短按/松开验证方向和停车，再验证后退距离、approach。烧录时电机独立5V断开，仅USB；不执行堵转或电流测试。
