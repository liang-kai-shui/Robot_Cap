# 3D 姿态方向与测距校正

## 3D 视角

网页的“模型朝向”按用户确认的安装角度改为 **90°**，默认“排针视角（+90°）”，并提供“排针视角（−90°）”及“芯片原始轴”对照；设置保存在当前浏览器。正方向定义为从传感器 +Z 一侧朝板面看逆时针。

坐标变换为 `Rz(π/2) R Rz(−π/2)`；反向选项使用 −π/2。用四元数执行完整变换，而不是直接交换横滚/俯仰数值，保证同时倾斜和转向时仍正确。以 +90° 为例，传感器 X 轴倾斜映射到模型 Y，传感器 Y 映射到模型 −X。这不是修改芯片的测量数据。姿态数字仍显示芯片原始读数；固件和电机转向控制使用的陀螺仪符号不变。航向失效时只冻结 yaw，仍显示有效的 roll/pitch，并标出“倾斜实时 · 航向失效”；不会把失效的航向当作有效数据。倾斜数据也失效或过期时模型冻结。模型只是模组示意。一次左右倾斜反馈不能确定芯片到车体的完整安装矩阵，需要对照实物左右、前后缓慢倾斜确认该视角是否符合安装方向。

实现使用本地 Three.js，离线数学测试验证坐标转换为正常旋转、倾斜方向变化、yaw 不变以及原始轴选项。参考 [Three.js Quaternion](https://threejs.org/docs/pages/Quaternion.html)。

## 距离读数比尺测多 2cm

本次按照尺测反馈设置 **−20mm** 固定偏移。网页增加“手动校正”输入和保存按钮，可在小车停稳时修改。

- 校正距离 = 原始距离 + 偏移。例如原始 93mm，校正后为 73mm。
- 网页、模型的 `get_distance()` 和 `approach()` 目标换算共用此值。
- 原始读数保留；近场提醒仍按原始读数判断。校正结果不大于 0 时作为无效读数，不显示负距离、不用于运动目标。
- 设置保存在本机 `runs/webui/range-calibration.json`，重启网页服务会读取，不保存密钥。
- 更改偏移会作废尚未执行的预览计划；任务或持续手动运动期间不能改偏移。

这是本次尺测提供的固定偏移，不等同于完成全量程标定。复核时应从镜头测量基准比对，并使用平整目标。原有“已知目标距离 → 标定偏移”仍会采集 20 个稳定样本，结果会替换手动校正。

## 电机供电检测已取消

用户目前没有分压电阻或检测模块，已要求取消新增的 5V 自动检测。相关检测代码和控制限制已撤回，原有 v1.9 固件与接线保留。USB、3V3 和串口 READY 不用于推断独立电机 5V 是否接好。

此次网页修改无需重新烧录，程序验证不驱动真实电机。

最终验证：465项Python测试通过（包含12项航向恢复专项测试），姿态坐标与部分有效数据的Node检查通过，原有v1.9固件编译通过。实车只执行连接/停止握手；原始95mm校正为75mm，未驱动电机。

## 相对转角空白与恢复

相对转角显示“—”时先看有效标志。当前诊断回传为 `yaw_valid=0`、`angle_valid=0`，但 BMI 通信 `error=0`、`calibrated=1`、倾斜 `tilt_valid=1`。因此角度空白来自固件的积分角度失效；90°模型坐标转换不会改变原始航向有效性。

固件在采样中断超过50ms、I2C读错或饱和后使积分失效，即使通信后来恢复，也不会把丢失的转角当作已测量数据自动补回。当前回传只能确认已失效，不能据此确定最初是哪种故障。

让小车停稳并保持静止，在3D姿态面板点击 **航向归零 / 恢复**。网页调用已有的串口 `z`，不启动电机、不需要烧录；必须同时收到 `ANGLE_ZERO_OK` 和递增 `zero_epoch` 的有效新航向样本才显示成功。新的相对转角以当前方向为零点，不恢复失效前丢失的角度。无法停稳、传感器未校准或样本过期时拒绝操作；超时不自动重试。

归零使尚未执行的计划失效，保留本次开机会话历史，记录一次参考零点变更。如果刚恢复又失效，请检查BMI接线及日志中的 `ANGLE_INVALID`，不要反复归零掩盖采样问题。
