## 设计计划

对象是桌面上的双轮ESP32实验小车，使用者需要直观地连接设备、查看实际反馈、点按动作并运行CaP任务。主视觉采用小车俯视硬件示意，让控制台的中心是实际设备。

| 色彩token | 数值 | 角色 |
| --- | --- | --- |
| 纸面白 | `#fbfcff` | 工作区与表面 |
| 工程蓝灰 | `#edf2f6` | 背景、分区和示意底板 |
| 深墨蓝 | `#182b40` | 文字、终端背景 |
| 控制蓝 | `#315fe9` | 主要动作与选中状态 |
| 传感器青 | `#249b9a` | 测量曲线与传感器标识 |
| 停止红 | `#c95050` | 停止与错误状态 |

文字采用系统中文无衬线字体，数值使用Bahnschrift/Segoe UI的数字排版；等宽字体用于终端和代码。所有资源随应用本地提供，不依赖在线字体或CDN。

布局草图：

```text
导航栏  | 设备连接、当前模式、停止按钮
        | 小车示意与最近回传      | 手动控制
        | 姿态/动作测量          | 自然语言任务与预览
        | 最近任务与计时         | 执行按钮
        | 串口/事件/命令终端，支持输入、过滤和下载
```

复查结果：减少重复的统计卡片和装饰性数字；用硬件示意、不同层级的测量区和终端表达实际工作流程。采用冷色工作区与蓝色控制标识，终端的深色专门用于日志阅读，避免整页变成统一的黑色模板。移动端将控制区和终端顺序排列。

## 交互原则

运行和未连接状态要可区分；未知值显示空缺，不填入模拟数字。演示模式有持续标记，传感器数据标注为演示。旧回传保留采样时间，不能冒充持续测量。

动作按一次执行一个有界步长，不排队、不自动重复。停止在页面顶部和控制区均可访问；输入框内输入文字不会触发运动快捷键。生成计划与执行计划分开，程序在服务器保留已校验的计划，浏览器不能改写动作代码后直接执行。

API密钥只在本机服务器当前进程保存，不写入浏览器持久存储、终端或运行记录。窗口失联、人工停止和动作故障使后续动作取消，需要明确重新连接后恢复。

已在浏览器检查 1440px 桌面和 390px 窄屏布局，窄屏没有横向溢出，并补齐设置、记录、终端、构建和说明入口。离线演示的连接、两段计划、按钮转弯、终端 status、内置说明正常；浏览器没有脚本错误。测距和定位仍显示当前不可用状态。

完整 Python 回归 400 项通过，包括 28 项 WebUI 测试；文档与 33 个固件文件校验通过。另用 pythonw 启动独立演示服务，验证没有 PowerShell 窗口时 Worker 动作仍完成并停稳。浏览器重启服务时发现旧令牌请求的 HTTP 连接复用问题，已修复并加入回归。以上不连接真实小车、不请求模型 API，也不进行刷写。

## 测距、轮子动画与3D扩展

在同一蓝灰工作台内加入独立距离区、左右轮动画和传感器板3D场景，不把控制按钮移入3D场景。3D模型显示BMI323板、排针及X/Y/Z坐标轴，保留数字读数和失效状态，OrbitControls只改变观察视角。侧栏控制区按自身高度排布，避免因新增图表被拉成长空白。

沿用已阅读的frontend-design skill；新增参考[Foxglove 3D](https://docs.foxglove.dev/docs/visualization/panels/3d)和[IMU Webserial Visualiser](https://github.com/MengLinMaker/IMU-Webserial-Visualiser)。采用本地Three.js 0.186.1，未复制参考项目的模型或控制代码。姿态使用既有传感器角度计算四元数；安装轴向未标定，没有声称完整AHRS或地面定位。

407项Python回归通过（含35项WebUI），轮速换算C检查及完整ESP-IDF构建通过。用户确认断开电机5V后，COM5烧录及镜像哈希验证成功。随后只发送连接/停止并观察实际静止数据，未运行电机。测距先出现光学status=7，之后收到有效status=0、133mm并显示为13.3cm；轮速为零，真实BMI姿态正常进入3D视图。浏览器验证拖动/复位视角，390px窄屏无横向溢出，没有脚本错误。

## 手动后退补充

手动方向区调整为W/A/停止/D/S布局，S按钮明确标注0.8秒。复用已有固件短时S模式，不假设已经有按距离后退能力；PC核对双轮编码器结果、定时完成及新READY。固定参数路径不进入模型能力清单，实际手动动作进入会话上下文，停止仍独立可调用。418项离线回归通过，浏览器演示按钮验证通过；未为此烧录或运行真实电机。
