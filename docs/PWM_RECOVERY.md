# 低 PWM 停止与故障重连

## pwm-stream-v5：手动小幅计数偏差

用户在 40% 架空及平地长时间测试正常、不平整桌面触发计数保护。已有 v4 故障帧包括 `forward_dq=36 edges=48`（40%）和 `forward_dq=100 edges=124`（100%）。边沿总数与净方向计数不相等也可能来自短暂回摆，不能仅凭该关系认定编码器损坏；仍不能排除干扰。

v5 对原计数检查失败的样本继续立即关断两轮。只有直接手动 PWM、净计数仍沿指令方向为正、总边沿为正、超出净计数的边沿不超过 32 且不超过总边沿一半时，改为 `TELEOP_END cause=MANUAL_ENCODER_VARIATION fault=0`。这只是停止后的恢复分类，不把异常计数用作有效运动反馈，也不允许继续输出。它不是已经标定的越障容许量，更不证明硬件正常。

网页显示小幅计数偏差提示，松开并等待停稳 READY 后，允许新的明确按下；续租心跳不能恢复旧按住，无需因为这次停止复位或重连。不提高 PWM、不自动重试。严重计数不一致、净方向反向、缺失通道表现、无反馈、GPIO 与控制时序检查，以及所有闭环动作的原锁定策略保留。重复发生应排查轮子、线缆牵拉及编码器信号。

验证：ESP-IDF 5.1.2 编译通过（应用 `0x4f370`），96 项相关 Python 回归通过；C 测试覆盖实际故障帧、32 边沿/一半比例边界、闭环禁止恢复、反向、无计数、异常累加和严重偏差；网页脚本语法检查通过。新增串口回放证明结束后 READY 与旧心跳不会重新运动，只有新按下开启新 session。

v5 已在用户确认电机 5V 断开后烧录至 COM5，停止握手确认 PWM v5、READY、无故障和两轮零转速；BMI/ToF 新鲜有效。仅发送停止，没有实车运动验证。可恢复停止只打印通知和被拒绝帧，避免长按后的整段 trace 阻塞停稳反馈；严重故障仍保留完整 trace。旧 27 条任务和故障事件已本地归档，复位后上下文清空，运行中 API Key 保留。运动效果待用户验证。

## 为什么以前重连经常失败

旧固件在任一轮 150ms 没有新的编码器边沿时触发 `NO_NEW_ENCODER_EDGES` 并锁定故障。`T` 只关断输出，不清除锁定；主循环也不会再发 `VEHICLE_READY`。因此网页重新打开 COM5 后，虽然能收到停止确认，却一直等不到 READY。

另外，遥控 WebSocket 在异常后会关闭，旧网页只在首次加载时建立它。串口重新连接成功，也可能没有恢复按住遥控通道。

## pwm-stream-v3 的处理

| 情况 | 结果 | 恢复 |
| --- | --- | --- |
| 直接手动 PWM 为 1–39%，任一轮 150ms 无新边沿 | 立即关断两轮，结束本次按住，提示 `LOW_PWM_NO_ENCODER_EDGES`；不锁定固件 | 检查供电、负载和编码器，调整后重新按下；不自动提高 PWM 或重新运动 |
| 直接手动 PWM ≥40%，任一轮 150ms 无新边沿 | 保留 `NO_NEW_ENCODER_EDGES` 锁定保护 | 排查问题，拔下电机独立 5V、保留 USB，按 EN/RST 后重新连接 |
| 闭环移动、转弯、接近等动作没有边沿 | 保留锁定保护 | 同上 |
| 编码器方向/计数一致性、方向引脚、控制时序异常 | 保留对应保护 | 按具体故障排查，不能靠重连绕过 |

40% 是本次“低 PWM 未检测运动”恢复分类的边界，**不是测量得到的电机最小起转值**。没有脉冲也可能是电源未接、接线或编码器问题；程序无法仅凭该现象断定原因。所有无边沿情况仍会停止，未延长 150ms 的反馈超时，也不进行堵转或电流测试。

固件在 `T` 的回复中增加 `fault=0/1`。`fault=1` 时，电脑立即提示锁定故障和复位方法，不再等完整握手超时。旧固件没有该字段时，超时信息区分“没有 STOP 回复”和“STOP 已确认但没有 READY”；不虚构串口已连接健康。

低 PWM 的结束通知按按住 session 匹配。延迟到来的旧通知不能结束下一次按住；结束后的心跳也不会在 READY 后重新启动，必须由人重新按下。

网页在健康设备恢复后重建关闭的遥控通道，重置序号、等待新的挑战令牌，且不重放原先的按键。按钮操作、松开停止、停止优先和失联保护继续保留。
